# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Regras de conteúdo, identidade Git e seções estão em `AGENTS.md` (leia primeiro). Resumo do que importa aqui: nunca dar push sem aprovação explícita (push em `main` publica direto), usar só a conta pessoal `marcelofrau`, e criar posts com o script, não à mão.

## Comandos

Blog estático Jekyll 4.3 sem testes nem lint. Validação = build sem warning + `_site/index.json` parseável.

O Ruby do Windows não compila as gems nativas; **nunca rode `bundle install`/`bundle exec` pelo Windows**. Use o WSL com o binário explícito `/usr/bin/bundle3.2` (o shim `bundle` do Windows sombreia o do WSL).

O projeto vive em `D:\workspace\_non_work_\sinal-e-ruido`, ou seja `/mnt/d/workspace/_non_work_/sinal-e-ruido` no WSL. O WSL precisa de `ruby-dev` pras gems nativas.

```powershell
# build (validação)
wsl -e sh -c 'cd /mnt/d/workspace/_non_work_/sinal-e-ruido && /usr/bin/bundle3.2 exec jekyll build'
# servir em http://localhost:4000/sinal-e-ruido/
wsl -e sh -c 'cd /mnt/d/workspace/_non_work_/sinal-e-ruido && /usr/bin/bundle3.2 exec jekyll serve'
# novo post (Node, roda no Windows)
node scripts/new-post.mjs <secao> ["título"]
```

Gems ficam em `~/.gems/sinal-e-ruido` via `.bundle/config`; nunca apontar `path` para dentro do projeto (Bundler recusa diretório world-writable em `/mnt`). CI (`.github/workflows/pages.yml`) usa Ruby 3.3 e faz deploy via Actions a cada push em `main`.

## Arquitetura

- **Seções** são a fonte única em `_data/sections.yml` (chaves fixas, hoje 7: inclui `ruido-branco`, o microblog). Elas alimentam a Personal Toolbar (`_includes/toolbar.html`), o taskpane e os links de categoria em `post.html`/`home.html` — **não** o desktop nem o menu Iniciar (só dentro do Netscape, por decisão do dono). Cada seção tem uma página em `_pages/<key>.md` (layout `category`, `category_key` = chave) e o post referencia a seção em `categories: [<key>]`. O `scripts/new-post.mjs` tem a lista de seções duplicada; ao mudar `sections.yml`, mude o script também.
- **`_pages` é uma collection** (`output: true`, permalink `/:path/`), não o `pages` padrão. Cada arquivo precisa de `permalink:` explícito no front matter.
- **Fragmentos** (`categories: [fragmentos]`) e **Ruído Branco** (`categories: [ruido-branco]`, microblog) não têm página própria na listagem: `home.html` e `category.html` renderizam o conteúdo inline — fragmentos via `_includes/fragment-card.html` (moldura "Bloco de Notas"), ruido-branco via `_includes/micro-card.html`. Posts normais viram `post-item` com título e `description`. Título é opcional nessas duas categorias, mas atenção: o Jekyll 4.4 preenche `title` de post sem título com o slug titleizado (`document.rb`: `Utils.titleize_slug`) — o fallback `default: 'Fragmento'` nunca dispara de verdade; um post `ruido-2611-2019` vira "Ruido 2611 2019" no h1 e no `index.json`.
- **`/index.json`** vem de `_pages/index.json` (Liquid + `jsonify`) e é consumido por `assets/js/random.js` (botão Aleatório) a partir de `data-baseurl` no `<html>`. Se mudar o formato do índice, ajuste os dois.
- **`assets/js/search.js`** só é carregado por `_layouts/archive.html` e filtra `li[data-text]` no cliente; `random.js` (qualquer `[data-random]`) é carregado por `default.html`.
- **Desktop / "SO"**: `_layouts/default.html` monta o desktop (ícones de `_data/desktop.yml`, sem as seções), a janela do Netscape (`titlebar` + `toolbar` + `masthead` + `sidebar` + `statusbar`), a barra de tarefas, o menu Iniciar e os `<template>` (`tpl-win`, `tpl-dlg-<id>`). `_includes/launchers.html` renderiza `desktop.yml` (poucos ícones, cabem numa coluna ao lado do Netscape); o menu Iniciar vem de `_data/startmenu.yml` via `_includes/startmenu.html` (recursivo: item com `items` vira submenu Programas ▸ Acessórios ▸ Jogos, abre no hover/`:focus-within`; o clique no `.sm-sub` não fecha o menu). Toda a lógica está em `assets/js/desktop.js`: janelas (arrastar, ▼/▲ do 3.11 e X do 98; qualquer `[data-act=close]` fecha a janela, e no Netscape abre a confirmação `tpl-dlg-close-browser`), taskbar, `data-open` (`browser`, `dos`, `notepad`, `shutdown`, `dlg:<id>`; o Bloco de Notas salva em `localStorage`), `data-cmd` da toolbar, throbber (`html.is-loading`). `data-open` vence o `href` (o handler global dá `preventDefault`; links só com `href` seguem normais). Além dos acima: `run` (Executar..., mapa `RUN` de nomes → `data-open`, URL vai pro `openInBrowser`, último comando em `sr.run`), `help` (janela win-help com a página `/sobre/` fatiada por `h2` em tópicos; usa `.page-body` de `page.html`), `logoff` (overlay + reload).
- **Popups de post**: `a[data-popup]` → `fetch` da página do post, extrai o `.post` e mostra numa janela em cascata, com `pushState` pra URL real do post (back fecha). Por isso o `post.html` precisa manter o `article.post` com o `h1`. Acesso direto à URL renderiza o post na janela principal.
- **MS-DOS**: js-dos v8 do CDN (`v8.js-dos.com/latest`), carregado só ao abrir; bundle em `site.dos_bundle` (`_config.yml`, exposto via `data-dos` no `<html>`). O `assets/dos/shareware.jsdos` é gerado por `scripts/build-dos-bundle.py` (os zips de origem ficam fora do repo; licenças em `assets/dos/FONTES.md`). Em `.BAT`, nunca use `|`, `<` ou `>` em `echo`.
- **Apps da época**: carregados sob demanda via `openApp()` (desktop.js expõe `window.__snr` com `makeWin`/`restore` pra scripts tardios). `assets/js/mirc.js` — mIRC fake: tab offline scriptada `#sinal-e-ruido` + IRC real por WebSocket (`wss://irc.swiftirc.net:4443`, redes grandes como Libera não publicam WS; Libera abre em popup por causa do CSP de frame). `assets/js/mines.js` — Campo Minado próprio (níveis, 1º clique seguro), zero deps. `assets/js/wordpad.js` — WordPad próprio (`contenteditable` + `execCommand`, salva em `localStorage`). Winamp: Webamp via CDN num `.webamp-host` próprio dentro do desktop (o `renderWhenReady` assume o nó inteiro: renderizar no `#desktop` apagava tudo); o host tem botão na taskbar e entra no `focusWin`/`minimize`/`restore` como janela, `onMinimize`/`onClose` do Webamp ligados a isso. Paint (`jspaint.app`), 3D Pinball (`pinball.alula.me`) e SkiFree via `openAppWin` (janela pelada: titlebar + iframe, uma por URL). O Pinball usa `crop`: a página dele desenha uma janela 98 falsa em volta do canvas, então o iframe é deslocado pra mostrar só o canvas 600×440 em (10,30), medido no headless. Ícones de Winamp e mIRC são os autênticos, extraídos dos instaladores oficiais (`assets/icons/winamp.png`, `mirc.png`); o resto vem do set alexmeub.
- **Exhibits de plugin morto** (nos Favoritos, grupo "Ressurreições", como páginas internas): `/eye4u/` (`_pages/eye4u.html`) — o site alemão de 2002 em Flash: SWF original completo `home/eye4u_1n.swf` (307 KB, 1175 frames, via Wayback) versionado em `assets/swf/`, rodando no Ruffle (`@ruffle-rs/ruffle@0.8.0` do unpkg; Wayback não manda CORS, por isso o self-hosting; verificado headless: WASM ok, SWF 200, console limpo). `/anfy/` (`_pages/anfy.html`) — o applet Java `AnLake` do Fabio Ciucci **não renderiza no CheerpJ 5** (AWT pixel-a-pixel quebra, tela branca no teste do usuário): a página é uma homenagem honesta em canvas puro, refletindo o `palio.jpg` do demo original de 2000 (`assets/java/palio.jpg` — único artefato Anfy mantido; o jar foi descartado).
- **Comentários**: giscus sobre GitHub Discussions do próprio repo. `_includes/giscus.html` só emite um placeholder `.giscus` com `data-*`; quem cria o `<script>` de verdade é `activateGiscus()` no `desktop.js` (o popup extrai o `.post` via `replaceChildren`, que não executa scripts — o mesmo vale pra página cheia, então uma única via). IDs `repo_id`/`category_id` chegam das Actions Variables via `scripts/prepare-giscus.mjs` no CI, gerando `_data/giscus.yml` gitignored; sem eles o include some e o post sai sem comentários. Categoria: "General" do repo (criar categoria dedicada exige UI; se um dia existir, mude `_config.yml` + a Variable).
- **Sidebar retrô**: botões 88x31 reais em `assets/img/88x31/` (origem em `README.md` da pasta) e contador de visitas em `[data-counter]`: `desktop.js` chama o abacus (`abacus.jasoncameron.dev/hit|get/<host>/sinal-e-ruido`, JSON + CORS, sem cookie), `hit` uma vez por sessão (`sessionStorage`), e só em `*.github.io` (local mostra 000000).
- **Tema** é CSS puro em `assets/css/site.css` (chrome 98/3.11 e Netscape 4; conteúdo em leitura moderna com detalhes retrô), sem framework. As fontes (Fraunces nos títulos, Newsreader no texto, IBM Plex Mono em metadados e código, Silkscreen nos rótulos pixel, só a 16px) vêm do Google Fonts mas ficam versionadas em `assets/fonts/` e são servidas pelo site, nunca pelo CDN do Google. O layout do conteúdo usa container queries em `.ns-content`/`.pop-page`, ou seja, responde ao tamanho da janela e não da tela. Ícones em três lugares: `assets/icons/` (PNGs 32px do set Windows 98 para desktop, diálogos e menu Iniciar, referenciados pelo nome sem `.png`); `assets/img/ns/` (toolbar do Netscape, recortes do tema Classic do Mozilla 1.x, MPL, com o README de origem); e `_includes/fa-sprite.html` (Font Awesome Free, CC BY 4.0, embutido como `<symbol id="fa-NOME">` e usado na sidebar; o `icon` e a `color` de cada seção estão em `sections.yml`; para um ícone novo, gere o sprite de novo a partir dos SVGs em `@fortawesome/fontawesome-free/svgs/solid/`). A bandeira do Iniciar é o ícone `windows-0` (16px). A faixa do título do post usa a `color` da seção (`--band`). O throbber é o GIF original do Netscape (`assets/img/netscape-throbber.gif`, sempre animado; o `.png` é o quadro parado usado com `prefers-reduced-motion`).
- **Conteúdo rico nos posts**: `{% include video.html youtube="ID" %}` (também `vimeo=` ou `src=` mp4; o iframe só entra no clique), `{% include link.html url=… title=… desc=… %}` (cartão de link) e avisos via IAL do kramdown (`> texto` + `{: .note}` / `.tip` / `.warn`). `image:` no front matter vira miniatura na listagem e imagem de topo no post. Includes usados dentro de Markdown precisam ter saída sem linha em branco e sem indentação (`{%- -%}`), senão o kramdown quebra o HTML. `assets/js/post-extras.js` (`window.snrEnhance(root)`, também chamado pelo popup) põe barra com "Copiar" nos blocos de código e carrega sob demanda do CDN o Mermaid (` ```mermaid `) e o KaTeX (`$$…$$`) só se o post tiver. `hero: banner` no front matter faz a `image:` virar fundo da faixa do título (em vez da figura abaixo); `image_caption:` é a legenda/crédito. A referência visual de tudo isso está em `/estilos/` (`_pages/estilos.md`, `noindex` e fora do sitemap).
- **Build local sem WSL**: `podman run --rm -v "<repo>:/srv" -v sr-gems:/gems -e BUNDLE_PATH=/gems -e BUNDLE_APP_CONFIG=/tmp/bundle -w /srv docker.io/library/ruby:3.3 sh -c "bundle install && bundle exec jekyll build"`, igual ao CI.
- **`baseurl: /sinal-e-ruido`**: todo link/asset local passa por `relative_url`; em JS use `data-baseurl` (veja `random.js`), nunca caminho absoluto.
